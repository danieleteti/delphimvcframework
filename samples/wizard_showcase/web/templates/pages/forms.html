Forms

The TemplatePro forms library (templates/lib/forms_bootstrap5.tpro) writes the Bootstrap markup of a control: label, control, current value and, when the field is invalid, the is-invalid class and the message. Each section below shows a control next to the line that produced it.

Every macro reads two variables unless told otherwise: formModel, where the value of the field comes from (an object, a dataset, a JSON object, a dictionary or a TStrings), and formErrors, field name → message. The handler puts both in ViewData: a fresh TFormsDemo on GET; on an invalid POST, Request.ContentFields (exactly what was typed) plus the messages, with status 422. Clear the name, type a future date or a quantity of 0 and submit.

{{raw}}{{import "../lib/forms_bootstrap5.tpro" as f}}   {{# once, at the top level of the page #}}{{endraw}}
{{if saved}}
Saved: every field passed the server-side validation. The form shows the values as the server stored them.
{{endif}} {{if formErrors}}
Some fields need attention (HTTP 422).
{{endif}} {{# novalidate: the browser lets everything through, so the messages you see come from the server #}} {{set formattrs := {"novalidate": true}}} {{set qtyattrs := {"min": 1, "max": 99}}} {{set notesattrs := {"maxlength": 500}}} {{call f.form("/forms", attrs=formattrs)}}
f.form — the <form> element

Called with call: everything up to endcall becomes the content of the form. attrs is a map of extra attributes; true writes a bare attribute (here novalidate).

{{raw}}{{set formattrs := {"novalidate": true}}}
{{call f.form("/forms", attrs=formattrs)}}
  ... the controls ...
{{endcall}}{{endraw}}
f.input — text, with placeholder and maxlength
{{>f.input("fullname", label="Full name", required=true, placeholder="First and last name", maxlength=60)}}
{{raw}}{{>f.input("fullname", label="Full name", required=true,
    placeholder="First and last name", maxlength=60)}}{{endraw}}
f.input — type email, with an icon prepended
{{>f.input("email", label="Email", type="email", required=true, prepend="✉")}}
{{raw}}{{>f.input("email", label="Email", type="email", required=true,
    prepend="&#9993;")}}{{endraw}}

prepend and append are written raw, so they can hold text, an HTML entity or an inline SVG.

f.select — options from a list of objects
{{>f.select("country", countries, label="Country", valueprop="Code", textprop="Name", empty="Choose a country", required=true)}}
{{raw}}{{>f.select("country", countries, label="Country",
    valueprop="Code", textprop="Name",
    empty="Choose a country", required=true)}}{{endraw}}

countries is a TObjectList<TCountry>: valueprop and textprop name the members used for the value and the text. With a list of strings, leave both out. empty adds a first option with an empty value.

f.checkbox
{{>f.checkbox("subscribed", label="Subscribe to the newsletter")}}
{{raw}}{{>f.checkbox("subscribed", label="Subscribe to the newsletter")}}{{endraw}}

A hidden input posts false, the box posts true after it when ticked: Request.ContentFields keeps the last value, so an unticked box reads false instead of being missing.

f.auto — one control per property

f.auto walks model.@@fields (the properties of an object, or the fields of a dataset) and picks the macro from the type: string → text, Integer → number, TDate → date, Boolean → checkbox, a property without setter → readonly. Below it renders the same TFormsDemo object; this form posts to the same handler.

From the type alone it cannot know that Country is a choice or Notes a memo: both become text inputs. Use the single macros when that matters, or change the metadata with TTProConfiguration.OnGetFieldMetadata.

{{call f.form("/forms", attrs=formattrs)}} {{>f.auto(demo)}} {{>f.submit("Save")}} {{endcall}} 
{{raw}}{{call f.form("/forms", attrs=formattrs)}}
  {{>f.auto(demo)}}
  {{>f.submit("Save")}}
{{endcall}}{{endraw}}
